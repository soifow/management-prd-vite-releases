# management-prd-vite-releases
management-prd-vite 桌面应用公开发布（Release）仓库，仅存放版本清单与发布产物，不含源码。

# 需求管理桌面应用 · 使用手册

> 一款面向**多项目并行**场景的本地需求与缺陷管理工具。所有数据保存在你的电脑本地，不依赖任何网络服务（智能导入功能除外）。

---

## 这是什么

「需求管理桌面应用」是一款 Windows 桌面应用，用于在本地管理多个项目的：

- **产品需求** —— 按「项目 → 模块 → 功能 → 迭代」组织
- **缺陷记录** —— 独立于需求，按级别与状态追踪，可关联到具体需求迭代
- **待办提醒** —— 基于完成时限，自动汇总到启动抽屉

适合**产品经理 / 项目经理 / 独立开发者**在日常工作流中记录、追踪、回顾产品迭代。

### 核心特点

- **完全本地化** —— 数据库与配置文件都在本机，不上云
- **多项目** —— 一个程序管理多个产品项目，各项目独立的模块、需求、Bug
- **Markdown 内容** —— 需求和 Bug 的描述用 Markdown 编写，支持表格、代码、列表
- **迭代式追踪** —— 同一功能在多次迭代中的变更以时间轴展示，点击节点即可跳转
- **子需求** —— 每个迭代可拆分为子需求列表，子项全部完成时提示将迭代标记为已完成
- **待办提醒** —— 根据完成时限与提醒阈值，启动时自动弹出待办抽屉；铃铛实时反映是否有新待办
- **Bug 独立管理** —— 缺陷与需求平级管理，五级严重度，可一键跳转到关联需求
- **.md 双轨导入导出** —— 机器可读（YAML frontmatter）+ 人类可读（Markdown 正文），导出后可手动编辑再导入
- **智能导入**（可选）—— 配置 LLM 接口后，可将任意格式的需求文档（Word / Excel / 纯文本）自动解析为结构化数据
- **数据可回滚** —— 任何导入操作前自动备份整库；支持从备份还原到任意备份点
- **单实例锁** —— 同一时间只允许运行一个程序实例，避免并发写库

## 启动应用

### 首次启动

- 双击桌面图标 `management-prd-vite.exe` 启动程序
- 程序在系统托盘无图标，作为前台应用运行
- 首次启动会创建默认数据目录（位于操作系统用户数据目录下），自动建库

### 多实例保护

- 同时启动多个程序会提示已有实例在运行
- 仅当有特殊调试需求时，可通过环境变量 `MANAGEMENT_PRD_ALLOW_MULTI_INSTANCE=1` 跳过此保护

## 数据存储

所有数据保存在**本机**的专属目录中，默认位置由操作系统决定（例如 Windows 上位于 `%APPDATA%` 下的程序专属目录）。

目录内：

- **数据库** —— `requment.db`（SQLite 文件，包含所有项目、模块、需求、迭代、子需求、Bug 及其关联）
- **设置** —— `settings.json`（提醒阈值、智能导入配置、备份保留数等偏好）
- **备份** —— `backups/` 子目录存放整库快照与回滚元数据

> 可在「设置 → 存储位置」中更换数据目录。更换时会自动把现有数据迁移到新位置，旧位置会被清理。

### 自动备份

程序在以下两种情况下**自动备份整库**：

1. **数据库结构升级** —— 升级到新版本触发表结构变更时，迁移前生成快照（命名形如 `requment.db.v{旧版本}.{时间}.bak`）
2. **导入前** —— 任何数据导入操作前，生成预导入快照（命名形如 `requment.db.preimport.{时间}.{id}.bak`）

迁移备份**永久保留**；导入备份仅保留最近 N 个（N 默认为 10，可在「设置 → 数据备份与回滚」中调整）。

如需从任意备份还原，在「设置 → 数据备份与回滚」中选中备份点即可。注意：还原是**破坏性操作**，会丢弃该备份点之后的所有改动。

## 界面导览

启动后，主界面由三部分组成：

- **左侧导航栏**（深色）—— 在工作区、Bug 管理、设置之间切换；待办铃铛和关于按钮位于底部
- **项目侧栏** —— 列出所有项目，可创建、删除、切换项目
- **主内容区** —— 当前视图的主体内容

顶部导航的图标（从上到下）：

- **工作区** —— 需求管理
- **Bug 管理** —— 缺陷独立管理
- **待办提醒**（铃铛）—— 自动汇总所有项目的未完成需求；铃铛亮起 = 有待办，静音 = 待办列表为空
- **关于**（位于底部）—— 查看版本号、检查更新、访问发布页
- **设置**（位于底部）—— 偏好与配置

## 工作区（需求管理）

工作区是需求管理的核心视图，每次聚焦一个项目。

### 视图模式

可切换两种聚合方式：

- **按时间** —— 把所有需求按「需求日期」聚合，相同日期的需求分到同一组；适合按周/按迭代回顾
- **按模块** —— 按功能所属模块聚合，模块名分组；适合按技术/产品域查看

切换是临时的——下次启动按设置中的「默认聚合方式」加载（设置 → 显示设置 → 默认聚合方式）。

### 项目层级

- **项目** —— 顶层容器（如「A 产品」「B 工具」），项目下有模块、需求、Bug
- **模块** —— 第二层分组（如「登录」「订单」「UI」），模块是一等实体；需求与 Bug 都可以关联多个模块
- **功能** —— 同一模块下的功能点；同名功能构成功能树的第三层
- **迭代** —— 同一功能在某一具体日期下的需求条目；同一功能可以有多个迭代（按日期排序）
- **子需求** —— 每个迭代可拆分为若干子条目，单独追踪完成状态

### 创建与编辑

- **新建项目** —— 项目侧栏顶部按钮，弹窗输入项目名后即可创建
- **新建模块** —— 通常在新建第一条需求/Bug 时通过选择器的「+ 新建」输入完成；也可在「功能详情」中通过模块选择器即时添加
- **新建需求** —— 在主内容区点「新建需求」按钮，弹窗输入：日期、所属模块（可多选、可即时新建）、功能名、状态、内容（Markdown）
- **新建迭代** —— 在「功能详情」中点「新建迭代」按钮，为该功能新增一个时间节点
- **新建子需求** —— 在「功能详情」当前迭代的子需求区添加，填写内容和状态

### 功能详情（核心交互）

点击树形视图中任意**功能**节点，进入功能详情页。

- **左侧**：当前迭代的 Markdown 编辑器（支持预览）
- **右侧**：该功能所有迭代的时间轴，点击任意节点可跳转到该迭代（编辑器内容随之切换）
- **头部控件**：迭代日期、所属模块（多选）、功能名、状态、完成时限——所有头部控件修改后即时落盘
- **内容自动保存**（设置开启时）—— 编辑 Markdown 内容时停止输入一段时间后自动落盘；可在「设置 → 显示设置」中调整自动保存间隔（1-20 秒）
- **删除迭代 / 删除功能** —— 在时间轴节点或详情页底部提供操作入口，操作前会二次确认

### 状态

需求的状态包括四种：

- **to do** —— 默认新建状态（待办）
- **等待对接** —— 自己的部分已完成，等待其他人配合
- **完成** —— 已完成
- **暂缓** —— 远期规划中，不计入完成度

把状态改为「暂缓」会自动清空完成时限；改回其他状态不会自动恢复时限，需手动重设。

### 完成时限

为需求设置一个截止日期。在「功能详情」头部右侧的日期选择器中选择。

- 留空 = 无时限
- 设置为「暂缓」会自动清空该字段

### 子需求进度

每个迭代可拆分为若干子条目。详情页底部会显示子需求清单。

- 当**当前迭代**所有子需求都已完成且该迭代本身未标为已完成时，会弹出建议完成该迭代的提示（可取消）
- 设置中可选择是否在树形视图的功能节点上显示「已完成/总数」的进度

## Bug 管理

Bug 与需求是平级但独立的两套数据。点左侧导航的「Bug」图标进入。

### Bug 的属性

- **所属项目** —— 与工作区共用当前项目
- **所属模块** —— 仅可从该项目已有模块中选择，**不允许新建**（保持模块口径一致）
- **内容** —— Markdown 描述，支持预览
- **级别** —— P0 核心缺陷 / P1 严重 / P2 高 / P3 中 / P4 低（按严重度由高到低显示不同颜色）
- **状态** —— 待修复 / 已修复
- **关联迭代**（可选）—— 链接到具体某条需求的迭代；支持在 Bug 详情中一键跳转到该迭代
- **日期** —— Bug 出现日期

### Bug 视图

- **按模块** —— 把 Bug 按模块分组
- **按时间** —— 按日期分组

支持按级别、关键字过滤。

### 关联失效

如果被关联的需求被删除，详情页中会灰显「关联已失效」并提供「清除关联」按钮；不会自动修改数据库。

## 待办提醒

启动程序时，**待办抽屉会自动弹出**（前提是存在未完成、且符合阈值的需求）。

- **已逾期**的需求置顶
- 剩余天数 ≤ 提醒阈值（默认 7 天）的归「即将到期」组
- 状态为「暂缓」的需求归「远期规划」组，**不受阈值影响**
- 剩余天数 > 阈值 且未逾期的需求**不出现**
- 设置中可选择是否将**无时限**的未完成需求常驻待办列表

点击待办项可跳转到对应项目和功能（自动切换侧栏项目、打开功能详情、定位到对应迭代）。

再次打开待办抽屉：点左侧导航的铃铛图标。

铃铛图标的亮/灭实时反映「是否有待办」。

## 导入与导出

### 导出项目

在工作区项目侧栏选中项目后，通过项目菜单选择「导出」。导出的文件是 **.md 格式**，采用**双轨结构**：

- 顶部是 **YAML frontmatter**（机器权威，包含所有 ID、关联、字段）
- 下面是 **Markdown 正文**（人类可读，用 `{#短锚点}` 装饰可跳转锚点）

> 导出的文件可作为**单文件项目快照**保存、版本管理、邮件发送；同时可在文本编辑器中直接阅读、编辑后再次导入。

导出时可选择是否包含 Bug。

### 导入项目

支持两种导入方式：

1. **标准导入** —— 选择 .md 格式的项目文件，按 frontmatter 解析
   - **导入到新项目**：1:1 还原所有 ID 和关联
   - **导入到已有项目**：按 `(feature, date)`、`(date, content)` 等键合并；已存在则更新，不存在则新建；ID 冲突自动重映射
2. **智能导入**（需先在「设置 → 智能导入」中配置 LLM 接口）—— 支持 Word（`.docx`）、Excel（`.xlsx` / `.xls`）、纯文本等多种格式
   - 程序先把文件转为结构化纯文本，再交给 LLM 识别
   - 解析结果先在预览面板展示，可勾选确认要导入的条目再提交
   - 智能导入只能创建**新项目**（中间格式不含原项目 ID）

### 导入前自动备份与回滚

每次导入前，程序都会对当前数据库做一次完整快照（含元信息记录到 `backups/manifest.json`）。若导入后数据不对，可在「设置 → 数据备份与回滚」中找到这次导入前的快照并还原。

## 智能导入（LLM，可选）

如希望让程序帮你把任意格式的需求文档自动解析为结构化数据，可在「设置 → 智能导入」中配置：

- **API 地址** —— OpenAI 兼容接口的基础地址（通常以 `/v1` 结尾）
- **API 密钥** —— 该服务商颁发的 API Key
- **模型名** —— 具体模型标识
- **超时（秒）** —— 单次请求超时（10-600 秒）

支持任何提供 OpenAI 兼容接口的服务（DeepSeek、通义千问、Kimi、ChatGLM 等）。

配置后，工作区顶部的「智能导入」按钮变为可用。

> API Key 以明文保存在本机 `settings.json` 中，请妥善保管本地设备访问权限。

## 设置

设置分七个分组（可在设置页内拖拽排序）：

### 存储位置
- **当前存储目录** —— 查看、更改数据存放位置

### 显示设置
- **默认聚合方式** —— 冷启动时工作区聚合模式（按时间 / 按模块）
- **项目列表日期** —— 侧栏每个项目显示的「最新」日期口径（最新需求日期 / 最新已完成日期 / 最近操作时间）
- **需求侧默认显示范围** —— 是否默认隐藏只含 Bug 的项目
- **名称截断长度** —— 长名称在头部/下拉框中的显示截断长度（0 = 不截断，仅影响显示）
- **需求列表默认展开全部聚合组** —— 冷启动时是否全部展开
- **Bug 列表默认展开全部聚合组** —— 冷启动时是否全部展开
- **自动保存** —— 需求/Bug 详情内容区编辑后是否自动落盘
- **自动保存间隔** —— 1-20 秒（仅在开启自动保存时生效）

### 提醒设置
- **提醒阈值** —— 剩余多少天内的需求进入待办（默认 7 天）
- **紧急阈值** —— 剩余多少天内聚合标题用紧急色（应 ≤ 提醒阈值）
- **提醒警告色 / 紧急警告色** —— 聚合标题的背景色，可自定义
- **无时限需求** —— 是否常驻显示无时限的未完成需求

### 子需求进度
- **功能节点显示子需求进度** —— 是否在树形视图功能节点后显示「完成数/总数」

### 智能导入
- 见上文「智能导入」配置项

### 数据备份与回滚
- **备份保留数量** —— 导入备份最多保留几个（迁移备份永久保留，不参与清理）
- **历史备份列表** —— 查看每次备份的元信息（触发原因、对应项目、时间、大小），可点击还原

### 版本更新
- **启动时自动检查新版本** —— 是否在启动时联网检查更新
- **关于** 页中也提供「立即检查更新」按钮

## 常见问题

**Q: 数据存在哪？能换电脑吗？**
A: 默认存在操作系统用户数据目录下。在「设置 → 存储位置」可改到任意位置。需要换电脑时，把整个数据目录（数据库 + 配置文件 + backups 子目录）拷贝过去即可。

**Q: 误删了项目/需求能恢复吗？**
A: 项目/需求删除前会弹窗二次确认，确认后无法在程序内恢复（无回收站）。但如果你之前做过导入操作，可到「设置 → 数据备份与回滚」中回到导入前的状态。

**Q: 同一个需求能属于多个模块吗？**
A: 可以。需求和 Bug 都可以关联多个模块，没有主从关系。

**Q: 暂缓状态的需求会出现在待办吗？**
A: 设置可剔除，如果打开该项设置，那么会，但永远排在「远期规划」组，不受提醒阈值影响。

**Q: Bug 能关联到具体某次迭代吗？**
A: 可以在 Bug 详情中设置「关联迭代」；保存后可在 Bug 详情中一键跳转到该迭代。如果被关联的迭代被删除，关联会失效（不会自动删 Bug）。

**Q: 导出的 .md 文件能手动编辑后再导入吗？**
A: 可以。但请保留 YAML frontmatter 块不被破坏（YAML 是机器权威源）；正文可任意修改（不会被解析）。所有引用都使用原始 DB ID，可放心调整描述。

**Q: 智能导入能处理 Word / Excel 吗？**
A: 支持 `.docx`、`.xlsx`、`.xls`、`.csv`、纯文本。旧版 `.doc` 不支持（请用 Word 另存为 `.docx`）。`.pdf` / `.pptx` 暂不支持。

**Q: 同时启动两个程序会怎样？**
A: 会提示已有实例在运行，避免并发写库。需要绕过此保护（如调试）可设置环境变量 `MANAGEMENT_PRD_ALLOW_MULTI_INSTANCE=1`。

## 适用与不适用的场景

**适用：**
- 单一用户 / 小团队的本地需求管理
- 多产品线并行，需要明确分项目追踪
- 希望用 Markdown 富文本描述需求细节
- 经常需要在「按时间」与「按模块」之间切换视角
- 希望把项目导出为可读、可版本管理的 .md 快照

**不适用：**
- 需要多人实时协作（程序仅本地、不联网同步）
- 需要复杂权限与审计（无用户系统）
- 需要与 Jira / 飞书项目等 SaaS 双向同步（无对接能力）
